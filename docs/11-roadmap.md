# 实施路线图

## 阶段 0：业务确认与原型（1–2 周）

- 访谈实际使用者，确认章程 B-01 至 B-07；
- 盘点现有商品、客户、供应商、库存和欠款数据；
- 实测扫码枪、打印机、纸张与 Windows/Android 设备；
- 输出销售开单、采购入库、往来对账的桌面/手机交互原型；
- 明确首期报表口径和验收样例。

退出条件：范围、业务口径、离线要求和设备清单书面确认。

## 阶段 1：可运行工程骨架（1 周）

- 创建 Tauri 2 + React/TypeScript、NestJS、PostgreSQL 工程及本地编排；
- 完成健康检查、OpenAPI、错误模型、日志、配置和 CI；
- Windows 与 Android 客户端登录到同一测试 API；
- 建立测试、迁移、格式化、静态分析和构建门禁。

退出条件：新机器按 README 可一键启动，CI 全绿，安装包可运行。

## 阶段 2：基础资料与权限（2–3 周）

- 用户、角色、权限、设备会话；
- 商品、分类、品牌、规格、单位/换算、条码、适配机型；
- 客户、供应商、仓库、资金账户；
- 导入预校验与操作审计。

退出条件：真实样例可导入，权限越权测试通过。

## 阶段 3：采购、销售与库存闭环（3–5 周）

- 采购入库/退货、销售出库/退货；
- 库存流水、余额、移动平均成本；
- 盘点、调拨、负库存并发控制；
- 打印/导出基础单据。

退出条件：端到端业务与库存不变量测试通过，现场扫码/打印可用。

## 阶段 4：应收应付与资金（3–4 周）

- 应收应付、收付款、预收预付、核销；
- 费用、其他收入、账户转账；
- 对账单、账龄、信用额度、冲销/月结。

退出条件：典型欠款样例逐笔与旧账核对，余额差异为零。

## 阶段 5：报表、可靠性和试运行（2–4 周）

- 经营看板、库存/销售/欠款报表；
- 自动备份、恢复演练、监控告警、性能压测；
- 一周以上真实用户试运行和问题修复；
- 用户手册、管理员手册和正式交接。

退出条件：满足上线验收门槛并有书面上线决定。

## 里程碑原则

- 时间为初步估算，阶段 0 确认后重估；
- 每阶段交付可运行、可测试、可演示的纵向能力；
- 不以页面数量衡量进度，以完整业务闭环和不变量验证衡量；
- AI、微服务、复杂离线、线上商城等不得挤占首版账本正确性。

## 首批开发任务建议

1. 写 ADR 锁定客户端/服务端/数据库及离线策略；
2. 建 monorepo、工具链版本文件和 CI；
3. 完成健康检查、登录和 OpenAPI 客户端生成；
4. 用“商品 + 仓库 + 库存查询”验证端到端架构；
5. 用一条采购入库过账验证事务、流水、审计和幂等；
6. 再扩展销售与往来账，避免同时铺开所有页面。
