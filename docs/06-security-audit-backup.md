# 安全、审计与备份

## 1. 安全目标

- 只有经过认证且有权限的人员可以查看或修改业务数据。
- 关键业务变更可追溯，敏感信息不泄露到日志、导出或备份。
- 设备丢失、网络攻击、误操作、数据库损坏时有明确处置与恢复办法。

## 2. 身份与会话

- 密码使用框架提供的强密码哈希，不自制加密算法。
- 登录失败限速与临时锁定；管理员重置密码需要审计。
- 短期访问令牌 + 轮换刷新令牌；刷新令牌只保存哈希并可按设备撤销。
- 桌面/手机令牌存入操作系统安全存储，不写明文配置或普通 SQLite 表。
- 管理员、冲销、大额调整等高风险操作建议支持二次认证。
- 离职或设备丢失时可立即禁用用户、撤销会话和查看最后活动。

## 3. 授权

- 使用角色 + 细粒度权限，例如 `sales.post`、`inventory.adjust`、`cost.view`。
- 默认拒绝；菜单隐藏不是授权，API 对每个用例再次校验。
- 关键数据可按仓库/门店扩展数据范围权限。
- 权限变更、管理员操作、导出和备份下载必须审计。

## 4. 数据保护

- 所有远程连接强制 HTTPS，数据库不直接暴露公网。
- 生产密钥来自安全配置/密钥服务，不提交仓库、不打入安装包。
- 客户身份证号使用 AES-256-GCM 加密保存；接口只返回末四位掩码。另存基于密钥的 HMAC 用于重复身份证检测，不以可逆明文或普通哈希参与查询。
- 客户人像在客户端缩放压缩后保存，只接受 JPEG、PNG、WebP，压缩后不超过 1.5 MB；人像属于敏感资料，查看和导出必须单独鉴权。本功能不做人脸识别或身份比对。
- 身份证 OCR 在客户端本地执行，证件原图不得上传或落库；语音识别可能由设备平台的在线服务处理，首次使用必须由操作员主动授权麦克风。GPS 只在主动点击定位后读取；配置第三方地址解析服务前必须评估客户位置数据的传输和留存条款。
- 附件限制类型、大小并随机命名；下载前鉴权，防路径穿越。
- 导出文件含敏感经营数据，应带导出人、时间水印并设过期清理策略。
- 日志脱敏：禁止记录密码、完整令牌、银行卡号、身份证号和请求体中的敏感字段。
- 依赖与容器镜像定期扫描，安全更新先在测试环境验证。

## 5. 审计日志

关键审计至少记录：

- 谁、何时、从哪个设备/IP；
- 对哪个业务对象执行什么动作；
- 成功/失败、原因和追踪 ID；
- 关键字段变更前后值（敏感字段脱敏）；
- 提交、过账、冲销、授权例外、导入导出和权限变更。

审计日志追加写入，普通业务用户不可修改或删除。审计不等同于调试日志，两者保留期和访问权限分开。

## 6. 备份目标

建议初始目标：

- RPO（最大可接受数据丢失）：24 小时以内；具备条件后提升至 1 小时。
- RTO（最大可接受恢复时间）：4 小时以内。
- 数据库每日完整备份；高频增量/WAL 归档是否启用取决于部署环境。
- 附件、配置、数据库分别备份但作为同一恢复点管理。

## 7. 3-2-1 备份策略

- 至少 3 份数据副本；
- 存在 2 种不同介质/存储；
- 至少 1 份异地或隔离，防勒索软件同时加密；
- 备份加密，恢复密钥与备份分开保存；
- `PII_ENCRYPTION_KEY` 必须与数据库备份分开托管并纳入密钥恢复演练；丢失该密钥后，已保存身份证号不可恢复；
- 自动任务失败必须通知负责人，不能只写一条无人看的日志。

## 8. 恢复演练

每月至少选择一个备份恢复到隔离环境，验证：

1. 数据库能启动并通过迁移/版本检查；
2. 用户、商品、最近单据、库存和往来余额可查询；
3. 流水与余额对账通过；
4. 随机附件可打开；
5. 记录恢复耗时、恢复点、问题与改进项。

未做恢复演练的“备份成功”不能作为可靠性证明。

## 8.1 当前应用内能力

- “系统设置 → 数据安全”已支持手动 PostgreSQL 自定义归档、SHA-256 与归档目录双重校验、下载和可信恢复点恢复。
- 覆盖恢复前会自动建立当前数据快照，并要求输入包含备份编号的确认文字；操作写入审计。
- 当前只覆盖业务数据库，不包含附件、PostgreSQL 集群角色/表空间和敏感字段加密密钥。
- 当前互斥锁和自动备份调度只覆盖单 API 实例；多实例部署前必须升级为共享维护锁和唯一调度器。每日自动备份、自动备份保留期清理、第二存储目录副本及经营看板失败提醒已经实现；操作系统推送/短信通知、云服务上传与外部归档导入仍属于后续运维工作。

## 9. 事件响应

发现异常时：隔离受影响设备/服务 → 保留日志与证据 → 撤销会话和密钥 → 评估数据影响 → 从可信恢复点恢复 → 对账 → 复盘与修复。不得在未留证前随意清理日志或覆盖数据库。
