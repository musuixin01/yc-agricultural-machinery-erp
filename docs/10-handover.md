# 项目交接说明

## 1. 交接目标

任何具备相应技术能力的新维护者，应能在不依赖原开发者口头记忆的情况下：搭建环境、运行系统、理解边界、定位问题、发布版本、备份恢复并安全修改业务。

## 2. 必交付内容

- 源代码与完整提交历史；
- 架构、模块、数据模型、API/OpenAPI 和 ADR；
- 本地开发、测试、构建、发布、回滚指令；
- 数据库迁移、初始化与期初导入说明；
- 配置变量清单（不包含真实密钥）；
- 客户敏感资料加密密钥 `PII_ENCRYPTION_KEY` 的安全托管、轮换和灾备移交流程（只移交密钥位置与权限，不把真实值写进本文）；
- 测试报告、已知问题、风险和未完成清单；
- 部署拓扑、域名/证书、备份位置与恢复演练记录；
- 桌面/Android/iOS 签名与发布账号的安全移交流程；
- 用户手册、管理员手册、现场设备清单；
- 数据字典、报表口径和账务不变量。

## 3. 账号与资产

建立资产登记表，包含所有者、用途、到期日、恢复方式：域名、服务器、数据库、对象存储、代码托管、CI、监控、证书、应用商店、签名密钥和备份密钥。真实密码通过密码管理器移交，不写入文档或聊天记录。

## 4. 环境复现验收

接手人从一台干净设备按照 README 完成：

1. 安装受支持工具链；
2. 启动本地数据库和 API；
3. 启动 Windows/Android 客户端；
4. 运行全部测试；
5. 创建示例采购、销售和收付款；
6. 从备份恢复测试环境；
7. 构建可安装发布包。

原开发者不得代替接手人操作。过程中遇到的隐含步骤必须补回文档。

## 5. 业务知识交接

- 商品编码、单位换算和适配机型规则；
- 移动加权平均成本与毛利口径；
- 应收应付、预收预付和核销逻辑；
- 过账、冲销、月结和调整流程；
- 负库存、最低售价、信用额度例外；
- 期初数据来源、清洗规则和核对结果；
- 打印模板、扫码/标签设备差异。

## 6. 已知风险模板

每项包含：编号、描述、影响、触发条件、临时绕行、长期方案、负责人、目标日期、状态。不得只写“待优化”。

## 7. 发布交接检查

- 当前生产版本和 Git 提交可对应；
- 数据库 schema 与迁移历史一致；
- 最近备份与恢复演练成功；
- 监控告警有接收人；
- 支持中的客户端版本明确；
- 未决安全补丁、数据差异和高风险缺陷已披露；
- 回滚与紧急停写流程实测。

## 8. 交接完成标准

接手人在无人代操作的情况下完成环境复现和一次演练发布；双方核对资产、风险、文档和恢复能力，并记录交接日期与责任边界。
