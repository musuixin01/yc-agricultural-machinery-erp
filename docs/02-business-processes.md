# 业务流程与账务规则

## 1. 单据状态机

所有会影响库存或欠款的单据统一采用以下概念：

```text
草稿 Draft → 已提交 Submitted → 已过账 Posted
     ↓              ↓
   已取消        退回草稿

已过账 → 已冲销 Reversed（生成独立反向单据）
```

- 草稿可编辑、可删除，不产生正式库存或往来账影响。
- 提交后等待授权人复核，可退回并写原因。
- 过账是一次原子事务：单据、库存流水、应收/应付和审计同时成功或同时失败。
- 已过账单据不可直接编辑或删除。错误通过冲销和新单纠正。
- 状态转换需要服务端权限、合法前置状态和幂等键。

## 2. 采购流程

当前首版代码先实现“采购入库单”，直接记录实际到货；尚未实现采购订单和分批收货。采购订单与采购入库单的业务含义不得混用。

```text
采购草稿 → 审核/确认 → 收货入库 → 采购过账 → 形成应付
                                      ↓
付款登记 → 付款过账 → 指定/自动核销 → 应付余额下降
```

关键控制：

- 收货数量不能为负；退货使用采购退货单；
- 采购退货按原采购价先减少原单未结应付，超过未结应付的已付款部分由供应商实际退款；库存按退货时移动平均成本减少；
- 同一订单允许分批到货，但累计收货不得无授权超订单；
- 采购入库更新移动加权平均成本；
- 现金采购可在同一业务动作内生成采购和付款，但保留两个可追溯单据；
- 预付款先进入供应商预付余额，采购过账后再核销。

## 3. 销售流程

当前首版代码先实现“销售出库单”，直接记录已经确认成交并实际交付的商品；尚未实现报价单、销售订单和分批出库。普通门店销售默认散客现结，只有客户赊账时才形成应收。

```text
扫码或选品 → 散客现结 / 客户赊账 → 销售草稿 → 库存/价格检查 → 销售过账 → 出库 + 收款或形成应收
                                                   ↓
选择客户欠款 → 确认收款并指定核销 → 资金增加 + 应收余额下降
```

关键控制：

- 门店忙时点击“扫码开单”直接进入散客现结，不显示客户登记步骤；
- 只有客户未结清货款时才切换“客户赊账”，此时必须选择已建档客户并填写付款日；
- 销售时间保存到秒，业务日期取门店当地成交日期；
- 扫码枪、手动条码或受支持手机相机识别商品条码后，自动带出商品和零售价；拍照识别商品当前仅为规划入口；
- 服务端在同一事务内锁定或并发校验库存，防止最后一件被重复售出；
- 现金销售仍产生销售与收款两类流水，方便对账；
- 销售退货引用原单优先，按原单位换算、税前/税后口径和成本规则处理；
- 销售退货表示客户现实中退回商品：累计数量不得超过原销售数量，商品按原销售成本回到原仓；赊账优先减少该原单未结欠款，已收款部分才形成实际退款。原业务事实录错但没有真实退货时使用冲销，不能冒充销售退货；
- 不允许仅修改客户余额解决错账；
- 低价、超信用或负库存的例外需要授权和审计。

## 4. 库存流程

### 盘点

1. 当前首版按仓库创建整仓盘点，自动冻结所有正库存商品的基准数量、成本和余额版本，无需逐个添加商品；
2. 操作员只录实盘数量，系统计算差异，不允许人工录入差异替代实盘；
3. 有差异的商品必须填写原因后才能提交复核；
4. 过账按固定商品顺序锁定余额。如果采购、销售或其他库存业务已改变任一基准余额，整张盘点拒绝过账并完整回滚，必须重新建立盘点；
5. 无差异行不产生库存流水；有差异行按原移动平均成本产生 `STOCKTAKE_GAIN` / `STOCKTAKE_LOSS` 流水，并把余额精确更新为实盘数量；
6. 已过账盘点及其流水不可修改或删除。当前未实现多人分区、零账面盘盈估价、盘点冲销和部分范围盘点。

### 报损

1. 明确损坏、锈蚀或已淘汰且无法销售的商品使用独立库存报损单；账实数量不明使用盘点，客户退回商品使用销售退货；
2. 草稿保存仓库、业务日期、商品、报损数量、原因和说明，提交复核前不改变库存；
3. 正式过账按固定商品顺序锁定当前库存。任一商品数量不足时整张单据失败并回滚，不允许部分过账；
4. 报损按过账时移动平均成本减少库存数量和价值；整项库存全部报损时使用余额精确总成本，避免舍入残差；
5. 过账写入 `INVENTORY_DAMAGE` 不可变库存流水、余额、幂等、审计和 outbox；已过账报损不能直接修改或删除；
6. 报损成本是经营库存损失，不自动生成法定总账或税务凭证。当前未实现报损冲销、残值回收、批次/序列号和照片附件。

### 调拨

同一数据库内调拨使用一张单据的出库与入库两条库存流水，必须同时提交。未来若存在异地在途，则扩展为“调出 → 在途 → 调入”，不可只减不增。

## 5. 收付款与核销

当前客户收款和普通供应商付款采用手工指定核销，款项必须全部分配到已有应收或应付发生项，不支持悬空未分配款项。客户预收款与供应商预付款均为独立业务事实：实际收付款时改变一次资金并建立可用余额，销售或采购过账形成欠款后再显式抵扣；不得用负应收或负应付代替。

- 收款、付款、退款和账户转账分别建模，不使用正负金额混淆业务含义。
- 核销关系独立记录：包含款项、业务单、核销金额、时间和操作者。
- 核销金额不得超过款项未核销额或业务单未结额。
- 供应商预付款抵扣不得超过预付款可用额或应付未结额，且抵扣本身不产生第二笔资金流水。
- 客户预收款抵扣不得超过预收款可用额或应收未结额，且抵扣本身不产生第二笔资金流水。
- 账户转账必须在一个事务内同时减少转出账户、增加转入账户并追加成对流水；两条流水净额必须为零，资金总额不变。
- 经营看板的销售净额按业务日期汇总销售原额并减去销售退货和错单冲销；不得通过排除已冲销原单后再减冲销额造成重复扣减。
- 看板中的客户欠款、我们欠供应商、资金余额分别直接读取正式未结应收、未结应付和资金余额，不得用历史销售/采购减收付款粗算。
- 取消核销不是删除记录，而是产生反向核销或标记撤销并记录审计。
- 当前客户收款和供应商付款都只支持整单反核销：原单与原核销永久保留，反向单据恢复相同欠款并逆转原资金影响；真实退款和退货必须使用各自业务单据。
- 自动核销默认按最早到期日/业务日期顺序，用户可手工指定。

## 6. 成本与毛利

首版普通商品采用移动加权平均：

```text
新平均成本 =（入库前数量 × 原平均成本 + 本次入库数量 × 本次单位成本）
             /（入库前数量 + 本次入库数量）
```

- 金额和成本在数据库使用 `numeric`，禁止二进制浮点计算钱。
- 销售过账时固化该次出库成本，之后采购价变化不改历史销售毛利。
- 退货、负库存例外、零库存后入库等边界需单独测试并记录规则。
- 整机若启用序列号，可按序列号记录实际采购成本。

## 7. 期间结账

- 每月可生成结账快照；结账前执行库存、应收、应付、资金和异常单据检查。
- 已结期间禁止新增或直接修改会影响该期间的已过账业务。
- 后续发现错误，在当前开放期间使用反向/调整单据处理。
- 结账不是删除历史，也不能替代数据库备份。

## 8. 幂等与重复提交

客户端对每次写请求生成唯一幂等键。服务端保存处理结果：同一个键、同一请求只能产生一次业务效果；键相同但请求内容不同必须拒绝并报警。打印失败或网络重试不得重复扣库存、重复形成欠款。

## 9. 审批建议

首版只做轻量审批：普通交易可由有权限人员直接过账；超最低售价、超信用额度、负库存例外、大额盘亏、历史冲销等高风险动作需要更高权限或第二人确认。阈值可配置，默认值在试运行期确定。
