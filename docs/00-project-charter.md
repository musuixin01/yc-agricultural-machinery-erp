# 项目章程

## 1. 背景

商户经营农机整机、农机配件、螺丝等商品。目前需要用一套系统替代分散的纸账或表格，形成从采购到销售、从库存到欠款、从收付款到审计的完整闭环，并可在店内电脑与手机上协同使用。

## 2. 产品定位

本系统是小微商贸经营 ERP，不是第一版就覆盖法定会计、税务申报、电子发票、工资或生产制造的综合财务软件。它首先解决四个核心问题：

1. 货是什么、在哪里、还有多少；
2. 从谁处以什么成本采购，卖给谁、售价多少；
3. 我们欠供应商多少，客户欠款多少；
4. 每个数字为何变化，能否追溯并纠错。

## 3. 成功标准

- 常用商品在 10 秒内可通过名称、助记码、条码、型号或适配机型找到。
- 销售、采购、退货和收付款都生成唯一单据编号。
- 已过账业务不允许物理删除；只能作废或冲销，并保留原因和操作人。
- 库存数量、应收余额、应付余额均可由业务流水重新计算核对。
- 任意客户或供应商能查看期初、发生额、收付款、余额和账龄。
- 每日自动备份；按计划完成恢复演练并记录结果。
- 桌面端和手机端使用同一套服务端规则，不出现两套账。
- 每个发布版本通过自动测试、迁移验证和基础安全检查。

## 4. 范围

### 首个可用版本（MVP）

- 用户、角色、权限、登录和操作日志；
- 商品分类、品牌、型号、规格、单位、条码、适配信息；
- 客户、供应商、联系方式、信用额度和期初余额；
- 采购订单/入库、采购退货、应付；
- 销售单/出库、销售退货、应收；
- 收款、付款、其他收入、费用、资金账户；
- 库存台账、盘点、调拨、报损报溢；
- 欠款对账、账龄、到期提醒；
- 经营看板、常用报表、单据打印/导出；
- 备份、恢复、导入和导出。

### 后续版本候选

- 多门店、多价格体系、会员和促销；
- 整机序列号、发动机号、保修与售后维修；
- 微信/短信提醒、线上商城、供应商协同；
- OCR 票据识别、智能补货、自然语言经营分析；
- 税务、发票和正式会计接口。

### 明确不在首版

- 法定总账、凭证、资产负债表和税务申报；
- 工资、人事、生产 MRP、复杂审批流；
- 未经人工确认由 AI 自动过账或自动付款；
- 高复杂度的多主离线冲突自动合并。

## 5. 角色

- 经营者/管理员：配置、授权、查看全部经营数据、执行月结和恢复。
- 销售：客户、报价/销售、收款登记，按权限查看成本和利润。
- 采购：供应商、采购、入库、付款申请/登记。
- 仓库：收货、出库、盘点、调拨；默认不查看资金与利润。
- 财务/记账：审核收付款、对账、费用和欠款报表。
- 只读审计：查询单据、流水、日志，不可修改。

小商户可以一人兼任多个角色，但权限模型仍必须保留，以便以后增加员工。

## 6. 基本约束

- 默认币种人民币，金额精确到分；数量至少支持 3 位小数。
- 时间存储采用 UTC，界面按 Asia/Shanghai 展示。
- 所有关键写操作由服务端校验并在数据库事务中完成。
- 不依赖客户端计算最终库存、欠款或利润。
- 首版优先支持 Windows 与 Android；iOS 保留工程能力，是否发布取决于设备和签名条件。

## 7. 待业务负责人确认

| 编号 | 决策 | 默认建议 |
|---|---|---|
| B-01 | 单仓库还是多仓库 | 数据模型支持多仓，首期启用一个主仓 |
| B-02 | 是否允许负库存 | 默认禁止；管理员紧急放行需记录原因 |
| B-03 | 成本计算 | 移动加权平均；整机可选序列号实际成本 |
| B-04 | 赊销信用控制 | 超额度警告，是否强制拦截由管理员配置 |
| B-05 | 完全断网是否必须开单 | 默认允许查缓存和保存草稿，不允许离线正式过账 |
| B-06 | 月结后能否改历史 | 禁止直接改，使用反向单据在新期间调整 |
| B-07 | 打印设备 | 先实测现有设备，再锁定纸张和驱动方案 |
