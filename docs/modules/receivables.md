# 客户欠款与收款核销模块

> 账务名称始终以玉春本店为主体：客户应向我们付款，因此经营界面统一称“客户欠款”。

## 业务边界

客户欠款只能由正式赊账销售过账形成，不能直接填写或修改客户余额。客户还款时建立独立的正式收款事实，并把收款金额指定核销到该客户的一笔或多笔未结应收。尚无欠款时可登记独立客户预收款，后续形成欠款后再抵扣，不使用负应收表示。

首版采用门店快速收款：操作员选择客户、收款账户和具体欠款，确认一次后立即正式过账，不另设草稿和提交步骤。该设计服务于忙时门店，但不能绕过服务端权限、幂等、并发和金额检查。

## 已实现范围

- 桌面端和手机端“客户欠款”正式工作台，不再显示模拟欠款。
- 按客户列出未结与部分结清应收、原欠金额、未结金额、销售单号和到期日。
- 一次收款可核销该客户的一笔或多笔欠款，并可对每笔选择全额或部分收款。
- 正式收款在一个 Serializable 事务内增加资金余额、追加资金流水、减少应收未结额，并写入核销关系、审计和 outbox 事件。
- 相同 `Idempotency-Key` 重试返回同一收款单，不重复增加资金或减少欠款。
- 收款金额不能超过实时未结欠款；并发变化时整笔事务回滚。
- 已入账收款支持整单反核销：恢复原核销的客户欠款，从原收款账户减少相同金额，并保留原收款与独立反核销记录。
- 已发生销售退货的相关收款禁止反核销；原账户余额不足时也会拦截，防止重复退款或负资金。
- 客户预收款入账时增加资金并建立独立可用余额；后续抵扣同时减少可用预收款和客户欠款，不产生第二笔资金流水。
- 客户对账单按业务日期重建期初、本期增加、本期减少和期末欠款，逐笔列示赊账销售、客户收款、销售退货、错单冲销、收款反核销及预收款抵扣。
- 客户对账单可从客户欠款工作台或客户资料行进入，支持 A4 打印、高清 PNG 保存与手机系统分享；查询本身不产生或修改欠款。
- 正式收款过账成功后自动打开“客户收款凭证”；历史收款也可从收款记录补打。凭证列示客户、实收金额、收款账户、业务日期、入账时间、经办人及逐笔销售核销关系。
- 客户收款凭证支持 A4、80mm 小票、高清 PNG 保存和手机系统分享；已反核销凭证保留审计信息并强制显示“已反核销，不能作为有效收款证明”。

## API

- `GET /api/v1/receivables/entries?customerId=:customerId`
- `GET /api/v1/receivables/receipts`
- `POST /api/v1/receivables/receipts`（必须提供 `Idempotency-Key`，确认后立即正式过账）
- `POST /api/v1/receivables/receipts/:id/reverse`（必须提供 `Idempotency-Key`）
- `GET /api/v1/receivables/advances`
- `GET /api/v1/receivables/statements/:customerId?dateFrom=YYYY-MM-DD&dateTo=YYYY-MM-DD`（单次最多 366 天）
- `POST /api/v1/receivables/advances`（必须提供 `Idempotency-Key`）
- `POST /api/v1/receivables/advances/:id/apply`（必须提供 `Idempotency-Key`）

查询要求 `receivables.read`，正式收款要求 `receivables.post`。

## 正式收款不变量

1. 客户必须启用且具有客户角色，所有核销项必须属于同一客户。
2. 每笔核销金额必须大于零，同一应收不能重复出现，合计金额由服务端 Decimal 精确汇总。
3. 核销不得超过事务锁定后的实时未结金额。
4. 收款单、核销关系、应收未结额、资金余额、资金流水、审计和 outbox 必须全部成功或全部失败。
5. 相同幂等键不得产生第二笔资金流水或第二次核销。
6. 已入账记录不可直接编辑；纠错必须通过独立收款反核销完成。
7. 收款反核销必须整单引用原收款和全部原核销关系；客户欠款恢复额与资金减少额必须等于原收款金额。
8. 已发生销售退货的下游销售单禁止直接反核销；已反核销收款不再阻止对应销售错单冲销。
9. 预收款原始金额不可改；可用余额只能由正式抵扣减少，且不得小于零或大于原始金额。
10. 预收款只能抵扣同一客户的有效未结应收，抵扣不得超过预收款可用额或客户欠款未结额。

## 已验证

- 正式数据库迁移与独立临时 PostgreSQL 业务验证均作为发布门禁。
- 临时库中客户欠款 `¥100`，收款 `¥40` 后未结为 `¥60 / PARTIALLY_SETTLED`，资金从 `¥20` 增至 `¥60`。
- 相同幂等键重复请求只保留一张收款单和一条资金流水。
- 对剩余 `¥60` 尝试核销 `¥70` 被拒绝，失败后资金和欠款均保持不变。
- 数据库触发器阻止已入账客户收款、核销关系和资金流水被直接修改或删除。
- `scripts/verify-receipt-reversals.ts` 在独立 PostgreSQL 数据库验证收款反核销、幂等、客户欠款与资金恢复、反核销后销售冲销，以及已有退货时的安全拦截。
- `scripts/verify-customer-advances.ts` 验证预收款入账、两次抵扣、资金不重复增加、幂等键复用拦截、超额抵扣与数据库不可变约束。
- `customer-statements.service.spec.ts` 验证跨期初、赊账销售、收款、退货、反核销和预收抵扣后的逐笔结余重建。
- `verify-customer-statement.mjs` 验证 375px 手机布局、高清 PNG、A4 渲染、HTML 转义和桌面弹窗宽度。
- `verify-customer-receipt-voucher.mjs` 验证多单核销、人民币金额大写、HTML 转义、反核销失效标识、手机横竖屏、A4/80mm 与高清 PNG 输出。
