# 数据备份与恢复模块

## 已实现范围

- 经营者可在“系统设置 → 数据安全”立即创建 PostgreSQL 自定义格式备份。
- 服务端生成归档后执行 `pg_restore --list` 结构检查，并计算 SHA-256 指纹；备份列表展示时间、大小、创建人、恢复点类型与校验状态。
- 可随时重新校验和下载已通过校验的备份。下载需要 `administration.manage` 权限并写入正式鉴权链路。
- 只允许恢复本系统创建且当前指纹仍一致的备份；必须输入“恢复 + 备份编号”二次确认。
- 恢复前自动创建 `PRE_RESTORE` 安全快照；正式恢复使用单事务和遇错即停，完成后重新连接数据库并写审计。
- 恢复完成后撤销数据库内全部设备会话，要求所有员工重新登录，防止旧恢复点中的会话凭证重新生效。
- 同一服务进程同一时间只允许一个备份或恢复任务。
- 可设置每日自动备份时间和保留 3–30 份自动备份；服务重启后从持久策略继续执行，页面显示下次执行、最近成功或失败信息。
- 保留策略只清理超额的 `AUTOMATIC` 恢复点，永不自动删除手动备份或恢复前快照。
- 可启用第二存储副本并填写服务主机上的绝对目录。每次自动备份成功后复制归档和元数据，重新计算 SHA-256 后才记为复制成功。
- 本机备份与第二存储状态分开记录：移动硬盘断开不会抹掉已经成功的本机备份；第二存储失败会在经营看板和数据安全设置中提醒有管理权限的用户。

## API

- `GET /api/v1/administration/backups`：查询恢复点。
- `POST /api/v1/administration/backups`：创建并校验备份。
- `POST /api/v1/administration/backups/:id/verify`：重新计算指纹并检查归档。
- `GET /api/v1/administration/backups/:id/download`：下载已校验归档。
- `POST /api/v1/administration/backups/:id/restore`：带确认文字恢复，恢复前自动快照。
- `GET /api/v1/administration/backups/policy`：查询自动备份策略和运行状态。
- `PATCH /api/v1/administration/backups/policy`：使用版本号更新启停、每日时间、保留份数、第二存储启停和目录。

以上接口均要求 `administration.manage`，前端菜单隐藏不替代服务端权限。

## 存储与配置

- 默认备份目录：项目 `data/backups`；可用 `YC_BACKUP_DIRECTORY` 指向独立磁盘。
- 当前开发环境通过 Docker 容器内的 PostgreSQL 官方工具执行；配置项为 `BACKUP_POSTGRES_CONTAINER`、`BACKUP_DATABASE`、`BACKUP_DATABASE_USER`。
- 备份文件为 `.dump`，同名 `.json` 保存指纹、大小、创建者和校验状态。元数据采用临时文件后原子重命名，避免半写入。
- 第二存储目录必须是服务主机可访问的绝对路径，不能与本机备份目录相同或互相包含；保存设置时会实际创建临时文件确认可写。
- 文件复制本身不假定为原子操作：系统先复制到唯一临时文件，校验 SHA-256 后再重命名为正式文件，并在最后写入同名元数据。
- 不在日志或元数据中保存数据库密码。

## 备份内容边界

- 包含 PostgreSQL `yc_erp` 业务库内的全部正式记录：商品、仓库库位、库存余额与流水、采购销售及退货冲销、客户供应商与数据库内人像、应收应付、收付款与预收预付、资金账户、员工权限、门店设置和操作审计。
- 不包含程序安装包、源代码、另存到设备的票据图片、数据库及应用密钥、PostgreSQL 集群角色/表空间，以及未来可能接入的数据库外附件目录。
- 身份证加密数据随数据库备份，但解密所需 `PII_ENCRYPTION_KEY` 不在备份中，必须分开安全保管。

## 运维要求与未覆盖范围

- 每日结束营业后至少创建一次备份，并启用另一块硬盘上的第二存储副本；仍应另有一份离店或可信云存储副本，执行 3-2-1 策略。
- 每月至少在隔离数据库做一次恢复演练。正式库恢复前必须通知其他员工停止开单。
- 当前为单 API 实例内存互斥；多实例部署前要改为数据库/基础设施级维护锁。
- 当前归档不包含 PostgreSQL 集群角色、表空间、附件目录、加密密钥；这些必须按同一恢复点分别管理。
- 自动定时、自动备份保留数量、第二存储副本和经营看板失败提醒已实现；操作系统推送/短信通知、云服务上传和任意外部归档导入尚未实现。
