# Parties 客户与供应商模块

## 目标与边界

Parties 维护所有往来单位。同一主体可同时拥有客户和供应商身份，避免名称、联系人和地址重复维护。本模块拥有主体资料、业务身份、联系人、信用额度和默认账期。

本模块不保存可手工编辑的应收或应付余额。客户欠款与供应商欠款必须由后续 Receivables/Payables 不可变发生与核销流水计算，信用额度只是销售检查的基础资料。

## 已实现能力

- A 桌面表格与 C 手机卡片共用 PostgreSQL 正式数据。
- 按编码、名称、简称、助记码、联系人或电话搜索。
- 按客户、供应商身份筛选，一个主体可同时具有两种身份。
- 新增主体、主要联系人、联系方式、地区地址、信用额度和默认账期。
- 赊账开单内可快速新增客户：人像排在姓名前，可拍摄、重拍和点击查看大图；身份证号码支持本地 OCR 拍照扫描及语音输入，地址支持语音和 GPS 定位。
- 客户身份证使用 AES-256-GCM 加密保存，接口只返回末四位掩码；人像压缩后保存且不参与人脸识别。
- 启用/停用；使用 `version` 乐观并发控制。
- 数据库保证编码、税号和同一主体的主要联系人规则。

## API

- `GET /api/v1/parties`：分页、搜索及身份/状态筛选。
- `GET /api/v1/parties/:id`：往来单位详情。
- `POST /api/v1/parties`：创建客户或供应商。
- `PATCH /api/v1/parties/:id/status`：按版本启停。

完整契约通过 `/api/docs` 查看。

## 数据规则

- 主体编码唯一，统一社会信用代码非空时唯一。
- 至少具有客户或供应商中的一种身份。
- 信用额度不得为负。新建赊账客户的默认账期按 0–120 个自然月保存，0 表示当天；旧有按天账期继续兼容。自然月计算遇到目标月份没有对应日期时取该月最后一天。
- 身份证号码必须通过 18 位格式和校验位校验；身份证拍照扫描只在当前设备本地运行 OCR，原始证件照片不上传、不保存。
- GPS 在未配置地图逆地理编码服务时只填写坐标，并要求操作员补充乡镇、村和门牌号。可通过客户端 `VITE_REVERSE_GEOCODE_URL` 配置返回 `address` 或 `display_name` 的服务。
- 同一主体最多一个主要联系人；未显式指定时，第一个联系人自动成为主要联系人。
- 主体不物理删除，停用后仍保留给历史单据引用。

## 验证与后续

自动化测试覆盖查询、不存在和并发冲突。真实数据库验收覆盖双身份创建、联系人电话搜索、供应商筛选、启停和过期版本 409 冲突。

尚未完成：资料编辑、多联系人维护、批量导入、身份认证/权限、审计，以及应收应付余额和对账单。上述能力不得由客户端模拟数据替代。
