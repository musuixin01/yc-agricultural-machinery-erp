# 库存账本与期初库存模块

## 已实现范围

- 独立“库存账本”桌面端与手机端页面，不再把商品档案中的安全库存误当成当前库存。
- 每个仓库可建立一张有效期初库存单，支持 `草稿 → 已提交 → 已过账`。
- 草稿按商品录入数量、单位成本和可选库位；金额由服务端 Decimal 计算并四舍五入到 4 位。
- 过账后生成不可变库存流水、库存余额、审计事件、幂等记录和 outbox 事件。
- 当前库存余额只读取已过账流水产生的余额快照。
- 库存页面采用双层模式：所有用户默认进入“日常库存”，只看真实数量、仓库和库存不足；拥有 `inventory.post` 权限的人可进入“专业账本”维护期初与正式库存单据。
- 日常库存支持按商品名称、编号或仓库搜索，并可只看低于或等于安全库存的商品。采购入库与销售出库仍通过各自业务模块自动影响库存，不在库存页面重复操作。
- 新增商品表单已合并“建档入库”：实物商品可同时填写当前数量、单位成本、仓库和日期，一次操作后自动生成已过账库存单据、库存流水、余额、审计和 outbox。库存页面不再提供新的期初库存入口，只保留历史期初记录。
- 已实现整仓库存盘点：选择仓库后自动冻结全部正库存商品的账面数量、成本和余额版本，操作员只录实盘数量，系统自动计算盘盈盘亏。
- 盘点支持 `盘点中 → 待过账 → 已过账`。有差异必须填写原因；正式过账写入不可变盘盈盘亏流水并将库存余额更新为实盘数量。
- 盘点创建后若任一商品发生采购、销售、退货或其他正式库存变化，整张盘点拒绝过账并回滚，防止旧快照覆盖新业务。
- 已实现独立库存报损：商品损坏、锈蚀或无法销售时建立报损草稿，保存原因后提交复核，正式过账按当前移动平均成本扣减库存。
- 报损不是盘点、销售退货或错单冲销；任一商品库存不足时整张报损回滚，不产生部分库存影响。
- 已实现库存流水明细查询：可按商品名称、编号、条码和业务类型筛选，展示仓库、数量增减、成本、原始单号、业务日期与过账人，并使用服务端分页。

## 关键不变量

1. 正式库存只存在 PostgreSQL，页面缓存和演示数字不是账本。
2. 单据只有提交后才能过账；已过账单据不能回到草稿，也不能直接修改明细。
3. 一次过账事务同时完成：状态、流水、余额、审计、幂等记录和 outbox。
4. `source_document_line_id` 唯一，重复幂等键不会重复产生库存影响。
5. 数据库触发器拒绝更新或删除库存流水；今后纠错必须新增关联冲销记录。
6. 余额数量必须等于相同商品和仓库的库存流水数量合计。
7. 服务类商品不能进入期初库存；库位必须属于所选启用仓库。
8. 建档入库仅允许商品在所选仓库没有任何库存流水时使用；相同商品再次到货必须使用采购入库，不能重复建立初始库存。
9. 建档入库的单据、流水、余额、幂等、审计和 outbox 必须在同一 Serializable 事务完成。
10. 同一仓库只能有一张盘点中或待过账盘点单；盘点差异只能由实盘数量减账面数量得到。
11. 盘点过账前必须按固定顺序锁定并核对全部基准余额；任一数量、成本或版本变化时整单失败，不得部分过账。
12. 无差异盘点行不写库存流水；盘盈盘亏按原平均成本计价，余额数量与流水数量合计必须继续一致。
13. 报损数量必须大于零且不得超过过账时当前库存；任一明细不足时整单回滚。
14. 报损按过账时移动平均成本出库；全部报损使用余额精确总成本，过账后余额仍可由流水重建。
15. 报损单、库存流水、余额、幂等、审计和 outbox 必须在同一 Serializable 事务中完成；已过账报损不可修改或删除。

## 已验证

- 独立临时数据库完整执行全部迁移和种子数据。
- 真实 HTTP 流程得到 `DRAFT → SUBMITTED → POSTED`。
- 数量 `3.5`、单位成本 `8.7654` 得到成本 `30.6789`，余额数量和流水合计均为 `3.5`。
- 同一幂等键重试后仍只有 1 条流水、1 条幂等记录、1 条事务审计、1 条 outbox。
- 无写权限员工调用创建端点返回 403；修改已过账单据返回 409。
- 直接 SQL 更新库存流水被数据库触发器拒绝。
- 独立临时数据库验证盘亏 `10 → 8` 后余额为 `8`、盘亏流水为 `-2`、成本变化为 `-10`，相同幂等键重试不重复。
- 独立临时数据库验证盘点基准版本过期时整单回滚：盘点仍为待过账且不产生任何盘点流水。
- 独立临时数据库验证报损 `10 → 7`、报损流水 `-3`、库存成本 `50 → 35`，相同幂等键重试不重复。
- 独立临时数据库验证两种报损商品中任一项库存不足时整单回滚，其他商品余额不变且不产生报损流水。
