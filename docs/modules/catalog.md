# Catalog 商品资料模块

## 目标与边界

Catalog 维护农机整机、配件、螺丝标准件、耗材和服务的基础资料，是采购、销售与库存模块引用商品的唯一来源。本模块管理商品编码、名称、类型、分类、品牌、单位、型号规格、售价、安全库存阈值和多条码。

Catalog 本身不拥有实际库存数量、库存成本或出入库流水。新增商品界面可同时发起 Inventory 的“建档入库”，但正式数量和成本仍由库存单据与不可变库存流水产生，不能保存成商品档案上的可编辑数字。

## 已实现能力

- A 桌面表格与 C 手机卡片共用同一套服务端数据。
- 按编码、名称、助记码、型号或条码搜索，最多返回 50 条。
- 创建商品，编码自动规范为大写；编码和条码数据库唯一。
- 新增实物商品时可同时填写当前数量、单位成本、仓库和日期；数量大于零时自动调用建档入库，服务类商品不显示库存字段。
- 商品已经保存但建档入库失败时，界面保留已建商品并只重试库存步骤，避免重复商品编码。
- 查询分类、品牌和计量单位基础资料。
- 启用/停用商品；使用 `version` 做乐观并发控制，避免覆盖他人的修改。
- 金额由 PostgreSQL `DECIMAL` 与 API 字符串传输，客户端只用于显示，不参与结算。

## API

- `GET /api/v1/catalog/references`：分类、品牌、单位。
- `GET /api/v1/catalog/products`：分页与搜索。
- `GET /api/v1/catalog/products/:id`：商品详情。
- `POST /api/v1/catalog/products`：新增商品。
- `PATCH /api/v1/catalog/products/:id/status`：按版本启停。
- `/api/docs`：OpenAPI/Swagger 调试页面。

## 数据与错误规则

- 主键使用 UUID；商品编码、条码唯一。
- 售价、进价、安全库存不得为负数；单位换算比必须大于零。
- 重复编码/条码、无效分类/品牌/单位、版本冲突均由服务端拒绝。
- 商品不做物理删除；停售使用 `INACTIVE`，从而给后续历史单据保留稳定引用。
- 建档入库要求 `inventory.post` 权限，只允许该商品在所选仓库没有任何库存流水时使用；后续到货必须走采购入库。

## 开发与验证

数据库由 `infra/compose/compose.yaml` 启动。迁移位于 `apps/api/prisma/migrations`，种子数据位于 `apps/api/prisma/seed.ts`。后端单元测试覆盖列表、重复数据映射和版本冲突；交付前还需执行真实数据库的创建、搜索和启停链路。
