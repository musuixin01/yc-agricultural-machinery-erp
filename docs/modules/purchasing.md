# 采购入库模块

## 业务边界

首版实现的是“采购入库单”：记录供应商实际到货并验收的数量与价格。它不是采购订单，不支持一张订单分批收货。后续实现采购订单时，由采购入库单引用订单行并控制累计收货数量。

## 已实现范围

- 桌面端和手机端采购入库工作台。
- 采购入库单 `草稿 → 已提交 → 已过账`。
- 按供应商、收货仓库、业务日期、付款到期日和商品明细录入。
- 正式过账同时生成库存流水、更新库存余额与移动加权平均成本、形成供应商应付、记录审计、幂等结果和 outbox 事件。
- 同仓库并发过账使用数据库锁、Serializable 事务和最多三次安全重试。
- 供应商应付列表只读取已过账采购产生的应付发生项。
- 已过账采购支持关联原单部分或整单退货；按原采购价先减少应付，已付款部分记录供应商实际退款到账。
- 退货库存按当前移动平均成本出库，累计退货不得超过原采购数量，当前库存不足时禁止过账。

## API

- `GET /api/v1/purchasing/receipts`
- `GET /api/v1/purchasing/receipts/:id`
- `POST /api/v1/purchasing/receipts`
- `PATCH /api/v1/purchasing/receipts/:id`（仅草稿）
- `POST /api/v1/purchasing/receipts/:id/submit?version=:version`
- `POST /api/v1/purchasing/receipts/:id/post`（必须提供 `Idempotency-Key`）
- `GET /api/v1/purchasing/payables`
- `GET /api/v1/purchasing/returns`
- `POST /api/v1/purchasing/returns`（必须提供 `Idempotency-Key`）

查询要求 `purchasing.read`，创建、修改、提交和过账要求 `purchasing.post`。

## 过账不变量

1. 只有启用且具有供应商角色的往来单位可以作为供应商。
2. 只有启用中的实物商品可以采购入库；服务商品不进入库存。
3. 到货数量必须大于零，采购单价不能为负，到期日不能早于业务日期。
4. 单据、库存流水、库存余额、应付发生项、审计、幂等记录和 outbox 在同一事务成功或失败。
5. 移动加权平均成本为：`(原库存总成本 + 本次入库金额) / (原数量 + 本次数量)`，使用 Decimal 并四舍五入到 4 位。
6. 已过账采购入库单和库存流水不可直接修改；纠错必须使用后续采购退货或冲销功能。
7. 相同幂等键只能对应一张单据；网络重试不重复入库、不重复形成应付。
8. 采购退货金额按原采购单价计算；应付减少与供应商退款之和必须等于退货总额。
9. 已付款部分必须选择启用中的到账账户，不得用付款反核销冒充真实退款。

## 已验证

- 独立临时数据库从零执行全部 26 个迁移和种子数据。
- 期初 `10 × ¥10` 后采购 `5 × ¥20`，最终数量 `15`、总成本 `¥200`、平均成本 `¥13.3333`、供应商应付 `¥100`。
- 同一幂等键重试仍只有一笔采购库存效果、一笔应付、一条事务审计和一个 outbox 事件。
- 同一幂等键用于另一单据返回 409，失败单据保持 `SUBMITTED` 且不产生部分账本影响。
- 两张同仓库采购单并发过账均返回成功；余额数量和成本与库存流水汇总一致。
- 无采购写权限的仓管账号调用创建端点返回 403；修改已过账采购单返回 409。
- 采购 `10 × ¥10`，先退 `3`、付款 `¥40`、再退 `4` 后，库存为 `3 / ¥30`，应付结清，供应商实际退款 `¥10`，资金与库存流水均可重建余额。
- 累计超退、库存不足和退货后付款反核销均被拦截；重复退货幂等键不重复生效，退货明细不可修改。
