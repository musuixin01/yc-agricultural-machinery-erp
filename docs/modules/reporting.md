# 真实经营看板

经营看板只汇总 PostgreSQL 正式账本，不读取 `mockData.ts`、页面缓存或手工填写余额。设计依据与竞品口径见 [真实经营看板模式调研](../research/erp-dashboard-patterns.md)。

## 已实现范围

- 今天、近 7 天、本月三种经营流量期间；“今天”统一按 `Asia/Shanghai`。
- 销售净额、退货金额、销售毛利；销售净额按销售原额减退货、减错单冲销计算。
- 客户欠款、逾期客户欠款、我们欠供应商及逾期应付，直接汇总正式未结余额。
- 启用资金账户余额合计；账户间转账不改变总资金。
- 启用商品跨启用仓库汇总库存，并按商品安全库存识别低库存和负库存。
- 最近销售、逾期客户、与“今天 / 近 7 天 / 本月”选择范围一致的净销售趋势和真实待办；所选范围没有销售事实时显示空状态，不绘制虚假波动。
- 桌面与手机共用 `GET /api/v1/reporting/dashboard`；接口要求登录和 `reporting.read` 权限。

## 口径底线

1. 销售、退货和错单冲销按各自业务日期记作正向或反向事实，不因当前状态重复扣减。
2. 客户收款不增加销售额；供应商付款不减少采购发生额。
3. 预收预付款未正式抵扣前不影响应收应付。
4. 资金余额只读取受资金流水约束的 `CashBalance`，不能用销售、收付款临时拼接。
5. “销售毛利”不是净利润；当前系统不具备费用和法定总账，禁止展示净利润。
6. 接口失败必须显示错误和重试，不能用零值掩盖故障。

## 验证

`apps/api/scripts/verify-dashboard.ts` 只允许连接名称包含 `_dashboard_verify` 的隔离数据库。验证销售、退货、跨日/同日冲销、应收、应付、库存预警、资金汇总和期间趋势，证明聚合结果可由明细复核。

尚需现场验证：真实门店数据下的长金额显示、老板实际关注顺序，以及手机小屏触控体验。
