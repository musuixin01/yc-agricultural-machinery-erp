# 付款与应付模块

> 账务名称始终以玉春本店为主体：我们向供应商付款，因此在本店账上属于应付；经营界面使用“我们欠供应商”避免视角混淆。

## 业务边界

本模块记录“我们欠供应商多少钱”和“从哪个资金账户实际付了多少钱”。应付发生项来自已过账采购；供应商付款单、付款核销、资金流水是三类独立事实，不能通过直接修改供应商余额代替。

普通付款必须全额指定核销已有应付。尚无应付时可登记独立的供应商预付款，后续采购形成应付后再执行预付款抵扣；预付款不得伪装成负应付。

## 已实现范围

- 桌面端和手机端“付款与应付”工作台。
- 现金、银行卡、微信、支付宝及其他资金账户，支持经核对的期初余额。
- 供应商付款单 `草稿 → 已提交 → 已过账`。
- 一笔付款核销一笔或多笔同供应商应付，金额由核销明细精确汇总。
- 正式过账在同一事务内减少资金余额、追加资金流水、减少应付未结额，并写入审计、幂等结果与 outbox 事件。
- 已过账付款支持整单反核销：独立反向单据恢复原核销的应付，把付款金额加回原资金账户，并保留原付款与核销历史。
- 供应商预付款正式过账时减少资金并建立独立可用余额；抵扣时只减少预付款余额和对应应付，不发生第二次资金收支。
- 正式付款过账成功后自动打开“供应商付款凭证”；历史付款也可从付款记录补打。凭证列示供应商、实付金额、付款账户、业务日期、入账时间、经办人及逐笔采购核销关系。
- 供应商付款凭证支持 A4、80mm 小票、高清 PNG 保存和手机系统分享；已反核销凭证保留审计信息并强制显示“已反核销，不能作为有效付款证明”。
- 供应商对账单按业务日期重建期初、本期增加、本期减少和期末欠款，逐笔列示采购入库欠款、供应商付款、采购退货、付款反核销及预付款抵扣。
- 供应商对账单可从付款工作台进入，支持 A4 打印、高清 PNG 保存与手机系统分享；查询本身不产生或修改应付。
- 资金余额不得为负；应付不能超额核销；资金流水由数据库阻止修改和删除。
- 资金账户、付款单与应付发生项使用行锁、Serializable 事务和最多三次并发重试。

## API

- `GET /api/v1/payables/cash-accounts`
- `POST /api/v1/payables/cash-accounts`
- `GET /api/v1/payables/entries?supplierId=:supplierId`
- `GET /api/v1/payables/statements/:supplierId?dateFrom=YYYY-MM-DD&dateTo=YYYY-MM-DD`（单次最多 366 天）
- `GET /api/v1/payables/payments`
- `GET /api/v1/payables/payments/:id`
- `POST /api/v1/payables/payments`
- `PATCH /api/v1/payables/payments/:id`（仅草稿）
- `POST /api/v1/payables/payments/:id/submit?version=:version`
- `POST /api/v1/payables/payments/:id/post`（必须提供 `Idempotency-Key`）
- `POST /api/v1/payables/payments/:id/reverse`（必须提供 `Idempotency-Key`）
- `GET /api/v1/payables/advances`
- `POST /api/v1/payables/advances`（必须提供 `Idempotency-Key`）
- `POST /api/v1/payables/advances/:id/apply`（必须提供 `Idempotency-Key`）

查询要求 `payables.read`，创建资金账户以及创建、修改、提交和过账付款单要求 `payables.post`。

## 过账不变量

1. 付款供应商、付款单和所有应付发生项必须属于同一个启用中的供应商。
2. 每个核销金额必须大于零，不得超过该应付发生项的未结金额；同一应付不能在一张付款单中重复出现。
3. 付款金额等于核销明细总和，使用数据库 Decimal；前端浮点数只用于即时展示，不作为正式金额来源。
4. 资金账户余额必须足够，数据库约束额外保证余额不能为负。
5. 付款单、核销、资金流水、资金余额、应付未结额、审计、幂等记录和 outbox 必须同一事务成功或失败。
6. 已过账付款单、核销关系和资金流水不可直接修改或删除；纠错必须生成整张付款反核销单。
7. 相同幂等键重试不重复扣款、不重复核销；并发抢付同一笔欠款时最多一个请求成功。
8. 付款反核销逐项恢复原核销金额，恢复后的未结应付不得超过原始应付；反核销金额必须完整加回原付款账户。
9. 付款反核销只更正误记付款，不表示供应商真实退款，也不能替代采购退货。
10. 相关采购已经发生退货时禁止付款反核销，因为退货的应付减少和退款拆分依赖付款状态。
11. 预付款原始金额不可改；可用余额只能由正式抵扣减少，范围始终为零到原始金额。
12. 预付款抵扣只能分配到同一供应商的未结应付，不得超额；抵扣不写资金流水。

## 已验证

- 在独立临时 PostgreSQL 数据库从零执行全部 27 个迁移和种子数据。
- 采购形成应付 `¥100`，付款 `¥40` 后应付为 `¥60 / PARTIALLY_SETTLED`，资金从 `¥1000` 降为 `¥960`。
- 相同幂等键重复过账返回同一付款结果，没有重复资金或核销影响。
- 两张付款单并发核销剩余 `¥60`，结果为一个 `201`、一个 `409 PAYABLE_OVER_ALLOCATION`；应付结清，资金最终为 `¥900`。
- 余额 `¥10` 的账户尝试支付 `¥50` 返回 `409`，付款仍为已提交，资金和应付均不发生部分变化。
- 仓管角色可查询应付但过账返回 `403`。
- 两个测试账户的资金余额均与资金流水汇总完全一致；直接更新资金流水被数据库触发器拒绝。
- 两次部分付款按不同顺序整单反核销后，应付恢复为 `¥100 / OPEN`，资金恢复为 `¥1000`，资金余额与流水汇总一致。
- 相同反核销幂等键只生成一张反向单据；反核销明细和已反核销原付款均被数据库触发器阻止修改。
- 预付 `¥300` 后资金由 `¥1000` 降为 `¥700`；抵扣采购应付 `¥60 + ¥40` 后应付结清、预付款可用余额为 `¥200`，抵扣过程未再次改变资金。
- 预付款与抵扣幂等重试不重复生效，超额抵扣被拒绝；预付款原单和已过账抵扣明细均被数据库触发器阻止修改。
- `verify-supplier-payment-voucher.mjs` 验证正式付款过账后自动预览、多单核销、人民币金额大写、HTML 转义、反核销失效标识、手机横竖屏、A4/80mm 与高清 PNG 输出。
- `supplier-statements.service.spec.ts` 验证跨期期初、采购、付款、退货、付款反核销和预付款抵扣后的逐笔结余重建。
- `verify-supplier-statement.mjs` 验证 375px 手机布局、横屏、高清 PNG、A4 渲染、HTML 转义和桌面弹窗宽度。
