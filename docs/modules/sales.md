# 销售出库与客户应收模块

> 账务名称始终以玉春本店为主体：客户尚未结清的货款在本店账上属于应收账款；经营界面统一使用“客户欠款”。

## 业务边界

首版实现的是“销售出库单”：记录已经确认成交并从指定仓库实际交付的商品。它不是报价单或可分批履约的销售订单。正式过账后统一产生负库存流水并固化销售成本；散客现结增加资金账户，客户赊账才形成应收发生项。

客户应收不是往来单位上的可编辑余额。当前模块只形成应收，客户收款与应收核销属于下一模块。

## 已实现范围

- 桌面端和手机端正式销售出库工作台，替换早期模拟开单页。
- 销售出库单 `草稿 → 已提交 → 已过账`。
- 默认使用“散客现结”快速开单，不显示客户登记步骤；系统只维护唯一内部散客对象，不会为每笔销售新增客户档案。
- 只有切换“客户赊账”时才要求选择已建档客户，并按客户账期计算付款日、形成客户欠款。
- 首页“扫码开单”直接打开散客现结销售窗并聚焦条码输入。
- 扫码枪或手动输入条码后回车即可自动带出有库存商品、数量 1 和零售价；重复扫码同一商品自动加一。
- 门店开单使用一个语义明确的快捷动作完成销售：现结为“完成销售并收款”，赊账为“完成赊账销售”。客户端仍依次调用创建、提交和过账接口，服务端状态机、库存锁、资金/应收分流和幂等事务均未被绕过。
- 快捷动作若在创建后失败，会显示单据已保留为草稿或已提交并禁止再次点击；操作员关闭窗口后从销售记录继续处理，避免重试产生重复销售单。
- 支持浏览器 `BarcodeDetector` 时可调用手机后置相机扫码；不支持时明确提示改用扫码枪或手动条码。
- 拍照识别商品仅展示“规划中”入口，当前不会上传图片或返回虚假识别结果。
- 实际成交时间 `soldAt` 精确到秒；`businessDate` 保存门店当地成交日期用于账务归期。
- 客户账期自动计算到期日；信用额度大于零时作为未结应收上限，零表示尚未设置限制。
- 已过账原销售单支持部分或整单销售退货；累计退货数量不得超过原销售数量，退回商品按原销售成本进入原仓库。
- 现结退货从退款账户减少资金；赊账退货优先减少该原单未结客户欠款，超过未结欠款的已收款部分才从退款账户退给客户。
- 已过账错单支持独立整单冲销：商品按原销售成本回原仓，现结从原收款账户退回销售款，未收款赊账撤销客户欠款；原单和冲销记录永久保留。
- 已发生退货的销售单不能整单冲销；已收到客户付款的赊账销售必须先完成收款反核销，反核销后的收款不再阻止销售冲销。
- 正式过账同步扣减库存数量与成本、追加不可变库存流水、固化销售成本和毛利，并根据结算方式二选一：现结增加不可变资金流水，赊账形成应收；同时记录审计、幂等结果与 outbox 事件。
- 禁止负库存；并发销售最后一件时最多一张单据成功。
- 销售价格不得低于商品已配置的最低售价；当前版本不提供低价授权例外。
- 已过账和已冲销销售单支持正式预览、浏览器打印、保存 PNG 图片和调用手机系统分享面板；已冲销单据始终带“已冲销”水印。
- 分享使用设备原生 Web Share 能力，可在支持的手机上选择微信；浏览器不支持文件分享时明确引导先保存图片，不伪装成已发送。
- 销售凭证读取 Administration 正式门店资料，并可按系统默认或本次临时选择打印 A4/80mm 小票；空电话和地址不显示。

## API

- `GET /api/v1/sales/documents`
- `GET /api/v1/sales/documents/:id`
- `POST /api/v1/sales/documents`
- `PATCH /api/v1/sales/documents/:id`（仅草稿）
- `POST /api/v1/sales/documents/:id/submit?version=:version`
- `POST /api/v1/sales/documents/:id/post`（必须提供 `Idempotency-Key`）
- `POST /api/v1/sales/documents/:id/reverse`（必须提供 `Idempotency-Key`）
- `GET /api/v1/sales/receivables?customerId=:customerId`
- `GET /api/v1/sales/returns`
- `POST /api/v1/sales/returns`（必须提供 `Idempotency-Key`）

销售查询要求 `sales.read`，创建、修改、提交和过账要求 `sales.post`；应收查询另要求 `receivables.read`。

销售退货列表同时返回全部正式退货单的 `summary.totalAmount`，用于销售页顶部展示“销售退货”总金额；该汇总不受最近 200 条明细列表上限影响。

创建或修改销售单必须传 `settlementType`、`soldAt`、`businessDate`、仓库和商品明细。`IMMEDIATE` 不传客户，`cashAccountId` 可省略并使用系统“门店现金”；`CREDIT` 必须传已建档 `customerId` 和 `dueDate`，且不能形成现金流水。服务端使用唯一内部散客对象承接现结销售的单据关系，该对象不会出现在客户档案列表中。

## 过账不变量

1. 现结销售只能使用唯一内部散客对象并关联启用中的资金账户；赊账销售必须使用启用且具有客户角色的已建档客户。出库仓库和商品必须启用。
2. 同一商品在一张销售单中只能出现一次；数量必须大于零，单价不能为负。
3. 服务端锁定客户、仓库和现结资金账户后重新检查实时库存；只有赊账才检查信用额度，客户端显示库存不作为过账依据。
4. 不允许未经授权的负库存；库存余额数量和成本必须分别等于库存流水汇总。
5. 销售成本使用过账时的移动平均成本；最后一件出库使用余额剩余总成本，避免舍入残差。
6. 销售单、成本快照、库存流水、库存余额、资金流水或应收发生项、审计、幂等记录和 outbox 在同一 Serializable 事务成功或失败。
7. 每张销售单的资金流水和应收发生项互斥：`IMMEDIATE` 只能有资金流入，`CREDIT` 只能有应收。
8. 已过账销售单和库存流水不可直接修改；纠错必须使用后续销售退货或冲销功能。
9. 销售退货必须分别记录退货商品总额、减少客户欠款和实际退款总额，并满足：退货商品总额 = 减少客户欠款 + 实际退款总额。
10. 销售冲销必须引用唯一原销售单并整单反向入账；有退货或已核销收款时禁止直接冲销，防止重复回库、重复退款或重复撤销欠款。

## 已验证

- 独立临时 PostgreSQL 数据库从零执行迁移和种子数据后，通过 `scripts/verify-sales-settlement.ts` 完整调用创建、提交和过账服务。
- `scripts/verify-sales-returns.ts` 验证现结退款、赊账减欠款、已收款部分退款、原成本回库、累计数量上限和库存/资金/应收对账。
- `scripts/verify-sales-reversals.ts` 在独立 PostgreSQL 数据库验证现结和未收款赊账整单冲销、原成本回库、资金/应收反向入账，以及已有退货和已有收款时的拦截。
- `apps/client/scripts/verify-sales-receipt.mjs` 使用真实浏览器内核验证 375 像素手机布局无横向溢出、桌面弹窗宽度、中文 PNG 生成、下载文件名、HTML 转义和不支持分享时的降级提示。
- `¥20` 散客现结过账结果：客户应收为零、`CASH_SALE` 资金流入 `¥20`、门店现金余额增加 `¥20`。
- `¥30` 客户赊账过账结果：形成客户应收 `¥30`，没有增加现结资金余额。
- 输入 `2026-08-31T03:12:45.000Z` 后数据库原样保存，确认销售时间没有被截断为日期。
- 自动化测试 12 个文件、36 项全部通过，客户端和 API 生产构建通过。
- 条码输入到商品自动带入已通过代码、类型和构建检查；相机扫码还需要在有相机权限的真实手机上做现场验证，不能用构建通过代替。
- 快捷完成销售的客户端生产构建已通过；仍需在真实扫码枪、手机和门店网络下验证连续扫码、断网中断及错误恢复体验。

## 尚未实现

- 客户预收款。
- 报价单、销售订单和分批出库。
- 当前销售退货入口只接受可重新销售并回到原仓的商品；损坏品、报废品和退回其他仓库的处理尚未实现。
- 草稿编辑界面、已提交退回草稿、折扣、税额、运费及授权低价销售。
- 拍照识别商品、整机序列号实际成本、批次、附件和 Excel 导入。
- 打印机纸张尺寸、实际 Windows 驱动、手机微信分享目标和门店抬头电话/地址仍需真实设备及门店配置验证；构建或浏览器自动化不能代替现场验收。
