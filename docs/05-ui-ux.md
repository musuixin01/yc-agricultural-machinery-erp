# UI/UX 与设计系统规范

## 1. 设计方向

采用现代、克制、信息密度适中的商用界面：清晰层级、大面积中性色、一个品牌主色、明确状态色、轻量圆角与阴影。避免大面积渐变、玻璃拟态、过度动画和“炫技式”仪表盘影响开单效率。

品牌名称为“玉春”，简称“YC”。主色使用深森林绿，辅助强调使用低饱和麦穗金/浅黄绿；桌面端保留高密度表格和深色侧栏，手机端使用暖灰背景、白色卡片和 YC 紧凑标识。品牌升级不得破坏业务信息密度或用装饰替代数据。

采用 Tailwind CSS 与项目自有的 shadcn/ui 风格组件形成设计系统，目标达到 WCAG 2.2 AA。组件源码归项目维护，但不得把第三方示例直接拼成风格不一致的页面。

## 2. 体验原则

- 高频优先：销售开单、扫码、收款、查欠款应最短路径完成。
- 桌面高效率：键盘快捷键、表格、批量录入、多窗口尺寸适配。
- 手机单手操作：底部主导航、重要动作在拇指可达区、扫码快速入口。
- 风险可见：过账、冲销、删除草稿、超信用等动作明确展示影响。
- 口径透明：金额卡片带时间范围，余额显示截至时间，报表显示筛选条件。
- 状态不靠颜色单独表达，同时使用文字、图标和形状。

## 3. 信息架构

### 一级导航

- 工作台
- 销售
- 采购
- 库存
- 往来账
- 资金
- 报表
- 基础资料
- 设置

桌面端使用可收起侧栏 + 顶部全局搜索；手机端保留 4–5 个高频底部入口，其余进入“更多”。权限不足的功能不显示，直接访问也由服务端拒绝。

## 4. 关键页面

### 工作台

展示今日销售/收款、应收/应付总额、逾期、低库存、待处理草稿与异常。数字必须可点击下钻，禁止只给漂亮卡片没有明细。

### 销售开单

- 顶部选择客户与仓库；
- 主区域商品搜索/扫码和明细；
- 侧边或底部结算区展示原价、折扣、应收、实收、欠款；
- 支持键盘上下选择、Enter 加入、数量快速修改；
- 过账前明确展示库存、信用和最低售价警告。

### 往来对账

顶部显示期初、增加、减少、期末；中部按时间列出业务与收付款；支持只看未结、账龄分组、打印/导出和逐项核销。

### 商品详情

基础信息、各仓库存、价格、适配机型、最近采购/销售、库存流水和附件分标签展示。手机端避免超宽表格，使用摘要卡 + 可展开明细。

### 库存双层模式

- 默认进入“日常库存”：店员只查看商品数量、仓库和库存不足，可按商品名称、编号或仓库搜索。
- 拥有 `inventory.post` 权限的人可切换“专业账本”，处理期初、成本和正式库存单据；没有权限的人不显示该入口，服务端仍是最终权限边界。
- 采购收货和销售完成后由业务单据自动增减库存，店员不需要再次到库存页面操作。
- 盘点、报损、调拨尚未实现时只说明状态，不显示可点击的虚假功能入口。
- 新增实物商品时把“当前数量、单位成本、仓库、库存日期”放在同一个表单中，数量为零则只建商品；数量大于零则后台自动完成建档入库。库存页面不再要求用户另建期初库存。

## 5. 设计令牌

代码前先在设计稿确认并集中定义：

- 品牌色、背景、表面、边框、文字、成功/警告/错误色；
- 4/8 像素间距体系；
- 4 档字号与 3 档字重；
- 紧凑/标准两种控件密度；
- 4、8、12 像素圆角层级；
- 桌面、平板、手机断点。

禁止页面自行硬编码颜色、字号、圆角和间距。

## 6. 表单与反馈

- 标签常驻，不用 placeholder 代替字段名；必填、单位和格式清楚。
- 校验靠近字段并给出修复办法；服务端错误映射到业务语言。
- 后台管理单据时，保存草稿、提交、过账、打印分别显示；门店快速销售可提供“完成销售并收款 / 完成赊账销售”快捷动作，由系统依次执行提交和正式过账，但不得使用含糊的“确定”，也不得绕过服务端库存、权限、账务和幂等校验。
- 快速销售中途失败时，必须告诉操作员单据已保留为草稿还是已提交，并阻止直接重复开单；操作员从销售记录继续处理。
- 长操作显示进度，可取消时明确可取消；失败保留用户输入。
- 重复点击过账只能产生一次结果。

## 7. 数据表格

- 固定关键列，列宽可调，筛选可保存，金额右对齐，状态统一徽标。
- 默认显示业务最重要列，不把所有数据库字段倾倒给用户。
- 桌面支持复制和导出；敏感列受权限控制。
- 空状态说明原因和下一步，错误状态提供重试与追踪编号。

## 8. 可访问性与本地化

- 正文与背景保持足够对比度；支持系统字体缩放。
- 触控目标至少约 44×44 逻辑像素，键盘焦点清晰。
- 日期、金额、数量统一按中文习惯格式化，但内部交换使用标准格式。
- 文案统一使用“客户欠款（应收）”“我们欠供应商（应付）”等业务可理解术语。
- 手机端主导航必须固定在视口底部并为系统安全区留白，不得要求用户滚动到页面底部才能操作；打开销售开单等专注型模态窗口时隐藏，关闭窗口后恢复。
- 手机端左上角经营者头像是账号功能固定入口，点击先打开窄型下拉菜单；当前只提供系统设置、切换账号和安全退出，更多低频功能进入系统设置后维护。头像触控范围不得小于 48px，入口不能只在宽屏右侧显示，也不叠加额外设置角标。
- 手机端销售开单使用带安全边距的屏幕居中窗口，优先保证扫码、结算方式、商品和提交操作可见；结算方式使用紧凑双列分段选择，说明文字不得挤占主要操作空间。
- “散客现结 / 客户赊账”固定在销售窗口最顶部，以图标和短标签紧凑切换；赊账时允许在当前销售单内快速填写客户姓名、电话、身份证号码、地址、账期并拍摄客户人像，保存后自动选中且保留当前商品，不要求退出开单页面维护客户档案。身份证和人像按敏感资料处理，界面不得回显完整身份证号。
- 赊账快速客户的人像入口排在姓名之前，有照片时点击缩略图查看大图并可单独重拍。身份证提供拍照 OCR 和语音入口；地址提供 GPS 定位和语音入口；默认账期按自然月选择。设备不支持、权限拒绝或 OCR 未识别时必须明确提示并允许手工录入。
- 销售开单窗口不重复显示页面级标题；扫码区下方必须紧接销售商品列表，初始为空，扫描一个商品后立即出现一条商品记录，重复扫描同一商品增加数量。
- 销售开单不显示仓库选择，后台使用启用中的默认仓库。商品可按名称、编号或条码输入检索，也可调用手机相机拍照后点选对应商品；没有正式识别服务前必须明确提示人工点选，不能伪装为自动识别成功。
- 门店标准路径为“扫码或搜索加入商品 → 核对数量和价格 → 完成销售”。重复扫码同一商品增加数量；散客现结不要求选择客户，默认仓库和收款账户不占用高频开单空间。

## 9. 设计验收

每个关键流程需有手机与桌面布局；至少覆盖正常、空、加载、无权限、校验失败、网络失败和并发冲突状态。只有静态漂亮页面而无完整状态，不算完成。
