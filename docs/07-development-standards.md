# 开发规范

## 1. 总原则

- 正确性、可读性、可测试性优先于炫技和抽象数量。
- 用业务名称表达意图；保持模块边界；重复两三行不一定比错误抽象更糟。
- 关键规则只有一个权威实现，客户端只做体验校验，服务端最终裁决。
- 改动必须包含必要测试、文档和迁移影响说明。

## 2. Git 与变更管理

- 主分支始终可构建；功能使用短生命周期分支。
- 使用 Conventional Commits，例如 `feat(inventory): add stocktake posting`。
- 一次提交/合并请求聚焦一个逻辑目标，不混入无关格式化。
- 禁止提交密钥、生产数据、构建产物、个人 IDE 配置。
- 合并前至少一人审查高风险账务/库存变更；无第二开发者时使用检查清单并保留自审记录。

## 3. TypeScript 与 NestJS 服务端

- TypeScript 开启严格模式；未知输入使用 `unknown` 并校验，不用 `any` 绕过类型系统。
- 控制器仅负责 HTTP 映射，不含业务规则或直接数据库操作。
- 应用用例明确事务边界；领域对象维护不变量；基础设施实现持久化。
- 异步调用必须 `await` 并传播取消/超时；后台 Promise 不得静默丢失异常。
- 钱在服务端使用 Decimal/定点值对象；明确舍入点；严禁 JavaScript `number` 参与正式金额结算。
- 查询默认投影所需字段；避免 N+1；性能优化基于测量。
- 异常分为预期业务错误与系统错误，统一转换 Problem Details。

## 4. React/Tauri 客户端

- React 页面组件只负责展示和交互，业务用例放在独立应用层/状态 hooks；服务端状态使用统一查询层。
- 网络 DTO、领域模型、展示模型按需要分离，不让 API 字段渗透整个 UI。
- 所有主题值来自设计系统；禁止散落 magic numbers 和颜色。
- render 中不发请求或做副作用；列表使用分页、稳定 key 和空/错/加载状态。
- 本地 SQLite 只存允许缓存的数据；迁移、设备撤销和退出登录清理策略必须测试。
- `src-tauri` 仅实现最小平台能力，不复制过账或账务规则；新增 Rust 权限和命令必须审查。
- 可复用组件首先解决明确重复，不建立无边界 `Common` 组件集合或万能全局 store。

## 5. 数据库

- 表/列使用一致命名；外键和唯一性由数据库约束。
- 每个迁移可审查、可在干净库和升级库执行。
- 禁止在生产手工改表后不补迁移。
- 所有查询参数化；动态排序/筛选采用白名单。
- 事务中不进行不可控的外部网络调用。

## 6. API

- OpenAPI 与实现同步；生成 TypeScript 客户端必须保持最新，新增/变更错误码、权限和幂等行为要写契约测试。
- 不返回数据库实体；使用显式请求/响应模型。
- 破坏性变化通过新版本或兼容迁移，不让旧手机端突然不可用。
- 日期时间采用 ISO 8601，金额用 JSON 数字并明确精度，ID 用字符串。

## 7. 测试要求

- 单元测试：纯业务规则、金额/数量、状态机、权限判断。
- 集成测试：真实 PostgreSQL 下的过账、并发、约束、迁移和回滚。
- 契约测试：OpenAPI 与生成客户端兼容。
- 客户端测试：状态控制器、关键组件、桌面/手机关键路径集成测试。
- 回归缺陷先添加能复现的测试，再修复。

## 8. CI 质量门禁

每次合并至少执行：格式检查、静态分析、编译、单元测试、集成测试、迁移验证、依赖漏洞检查、密钥扫描。主分支发布另加安装包构建、端到端冒烟测试和产物签名检查。

## 9. 禁止模式

- 巨型 `Service`/`Manager`/`Utils` 承担多个模块职责；
- 控制器、页面或定时任务复制同一套账务规则；
- 捕获所有异常后静默返回成功；
- 用字符串散落表示状态、权限和单据类型；
- 为赶进度直接改余额或删除已过账数据；
- 未经验证引入新框架、消息队列、缓存或微服务；
- 将“可以编译”等同于业务正确或可上线。

## 10. 完成定义（DoD）

需求与验收标准明确；代码已审查；测试通过；安全与权限检查完成；迁移和回滚路径验证；日志/指标可诊断；用户文档与 API 文档更新；桌面和手机关键状态实测；不存在未说明的高风险 TODO。
