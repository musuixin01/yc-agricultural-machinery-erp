# AI/人工代码审查清单

只检查与变更相关的分支，但相关分支内每项必须有结论。

## 边界与结构

- [ ] 改动属于正确模块，没有绕过模块公开接口直接改别人的数据
- [ ] 控制器/React 页面/Tauri Rust 外壳未承载服务端权威业务规则
- [ ] 没有新增万能 Service、Utils、Common 组件或全局 store
- [ ] 新依赖有必要性、官方支持状态、锁定版本和退出方案

## 账本与事务

- [ ] 已过账记录通过冲销/调整纠错，不被覆盖或删除
- [ ] 单据、库存、应收/应付、资金、审计和 Outbox 在正确事务边界内
- [ ] 余额可以由流水核对，派生快照有一致性检查
- [ ] 金额、数量、单位换算、精度和舍入明确且不用浮点结算
- [ ] 失败完整回滚，重复请求幂等，并发不会超卖或超额核销

## 安全与隐私

- [ ] API 每个用例执行身份、权限和数据范围检查
- [ ] 输入经过校验，数据库查询参数化，附件路径/类型/大小受控
- [ ] 密钥、令牌、密码和客户敏感信息未进入代码、日志、错误或测试夹具
- [ ] 高风险动作、导入导出和权限变化有审计

## 客户端与离线

- [ ] SQLite 只保存允许的缓存/草稿，显示缓存时间并处理 schema 迁移
- [ ] 断网恢复后由服务端重新校验，草稿不会被误显示成正式单据
- [ ] 客户端重试不会重复生效，冲突信息可理解且不会丢用户输入
- [ ] 桌面键盘/表格和手机触控/扫码状态都已考虑

## 数据与发布

- [ ] 数据库迁移可在干净库和升级库执行，兼容/回滚路径明确
- [ ] OpenAPI 与生成客户端同步，旧客户端兼容边界明确
- [ ] 日志、指标和错误关联 ID 足以诊断失败
- [ ] 备份/恢复或生产配置影响已更新运维文档

## 证据

- [ ] 相关单元、PostgreSQL 集成、契约和端到端测试通过
- [ ] 回归缺陷有复现测试
- [ ] Windows/Android/打印/扫码等现场事项与自动测试证据分开报告
- [ ] 未验证项、风险和后续责任人已明确
