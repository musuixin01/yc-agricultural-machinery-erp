# 测试与验收计划

## 1. 测试策略

风险从高到低：账务/库存一致性、安全权限、数据迁移与恢复、核心开单流程、兼容与体验。测试数量不是目标，关键不变量与真实失败模式才是目标。

## 2. 自动化测试分层

- 单元测试：状态转换、单位换算、舍入、成本、信用和核销规则。
- 集成测试：真实 PostgreSQL、事务回滚、并发、幂等、外键/唯一约束。
- API 契约测试：状态码、Problem Details、分页、版本和权限。
- 客户端组件测试：表单、错误状态、权限隐藏、设计系统。
- 端到端测试：登录 → 建商品/往来单位 → 采购 → 销售 → 收付款 → 对账。
- 恢复测试：从备份恢复后执行一致性检查与冒烟业务。

## 3. 账务不变量

任何版本必须自动验证：

- 库存余额 = 该粒度所有已过账库存流水之和；
- 应收余额 = 应收发生 - 已核销收款/退货/调整；
- 应付余额 = 应付发生 - 已核销付款/退货/调整；
- 核销金额不超过款项和业务单可核销余额；
- 冲销单与原单在相应账本的净影响为零；
- 已过账单据不能被普通更新/删除；
- 同一幂等键不会产生第二次业务影响；
- 无权限用户即便直接请求 API 也被拒绝。

## 4. 必测业务矩阵

| 场景 | 关键验证 |
|---|---|
| 现金采购 | 库存增加、应付形成并被付款核销、资金减少 |
| 赊购/部分付款 | 应付余额和账龄准确 |
| 散客现结销售 | 库存/成本减少、资金流入且不形成应收、毛利正确 |
| 客户赊账销售 | 库存/成本减少、只形成客户应收且不增加资金、毛利正确 |
| 赊销/部分收款 | 应收余额、额度、账龄准确 |
| 销售退货 | 原销售关联、回库成本、退款/应收冲减 |
| 采购退货 | 可退数量、库存减少、应付冲减 |
| 盘点 | 基准、实盘、差异、过账和审计完整 |
| 并发卖最后一件 | 最多一笔成功，不出现未授权负库存 |
| 网络超时后重试 | 不重复过账，客户端能取得原结果 |
| 月结后纠错 | 历史不改，新期间反向/调整正确 |
| 权限越权 | 页面与 API 都拒绝并记录审计 |
| 导入脏数据 | 正式写入前拦截并报告行级错误 |

## 5. 性能与稳定性

- 使用接近容量基线的数据测试商品检索、单据列表、账龄和报表。
- 模拟 10 个用户并发开单、查询与核销，记录 P50/P95/P99。
- 对慢查询分析执行计划；不通过盲目加缓存掩盖模型问题。
- 执行长时间稳定性、断网/恢复、服务重启和数据库连接耗尽测试。

## 6. 客户端验收

- Windows 常见分辨率、125%/150% 缩放、键盘与扫码枪；
- Android 小屏/大屏、相机扫码权限、返回键和弱网；
- 字体放大、对比度、键盘焦点、触控目标；
- 空数据、超长名称、大金额、小数数量、超宽规格；
- 安装、升级、本地缓存迁移、退出登录和设备撤销。

## 7. 用户验收（UAT）

从真实业务选取匿名样例，由实际使用者在测试环境完成连续一周试运行。每天对照纸账/旧表核对库存、客户欠款、供应商欠款和资金流水。问题按阻断/严重/一般/建议分类；阻断和严重问题关闭后才可上线。

## 8. 上线验收门槛

- 所有高风险用例通过，未关闭缺陷有明确接受人和绕行方案；
- 期初数据总额与抽样明细核对签字；
- 备份、恢复、回滚和监控告警已实测；
- 管理员、普通员工权限实测；
- 打印机/扫码枪在现场设备实测；
- 用户手册与交接清单完成；
- 试运行后库存、应收、应付差异为零或有书面解释。
