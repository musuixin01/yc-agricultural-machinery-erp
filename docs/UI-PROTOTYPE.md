# UI 原型评审与选型说明

> 选型状态：已确认采用 AC 组合——A 做桌面端，C 做移动端。

## 原型问题

在正式编写业务功能前，确定这套农机 ERP 应采用哪一种信息架构和视觉方向，并验证桌面高密度经营与手机快速操作能否共存。

## 运行

在项目根目录执行：

```powershell
pnpm install
pnpm ui
```

原型根据窗口宽度自动选择：宽度大于等于 761 CSS 像素使用 A，低于 761 使用 C。

页面参数 `screen=dashboard|sales|inventory|debts` 可直达工作台、销售、库存或欠款模拟页面，例如 `?screen=sales`。

## 三种方向

### A：田野中枢

桌面侧栏、信息密集、业务模块直达。适合店内电脑长期使用，工作台、图表、欠款与快捷操作平衡。手机端自动切换底部导航。

### B：账本工作台

强调经营流水、资金流入流出和待处理风险，视觉更克制，更像现代专业财务软件。适合经营者和对账人员，但仓库员工初次使用可能需要适应。

### C：移动门店

手机与触控优先，大卡片、底部导航、扫码入口和联系/收款动作更突出。桌面仍可用，但数据密度低于 A/B。

## 已确认方案

- 桌面端保留 A 的左侧导航、经营指标、图表和高密度业务区。
- 移动端保留 C 的底部导航、扫码入口、大触控区域和卡片式业务信息。
- 页面切换采用原生 View Transitions 渐进增强，并提供 CSS 回退。
- 卡片进入、图表绘制、按钮按压和导航反馈使用短时 GPU 友好动画。
- 系统开启“减少动态效果”时关闭非必要动画。

## 原型边界

- 所有客户、商品、金额、库存均为虚构模拟数据。
- 按钮只切换页面或展示交互，不写数据库。
- 原型代码明确为抛弃式探索代码，没有正式错误处理、权限、测试和 Tauri 外壳。
- 选定方案后，正式页面需按项目架构、测试、安全与账务规则重写，未选方案从主开发路径移除。

## 当前验证证据

- TypeScript 严格检查与 Vite 生产构建通过。
- A/B/C 桌面首页均已在 1440×1000 视口实际渲染截图。
- C 手机首页和销售开单已通过 Playwright 在真实 390×844 CSS 视口渲染。
- 两个手机页面均验证 `innerWidth = 390` 且 `documentElement.scrollWidth = 390`，没有横向溢出。
- 截图保存在 `apps/ui-prototype/screenshots/`，用于评审而非正式视觉回归基线。
